# M1 Register and pass

## Gate

From a fresh install: the setup wizard connects a real sheet and Gmail, an admin creates an event with three custom fields, a participant registers on a phone, the pass email arrives within 60 seconds with inline QR, PNG and PDF, and the Participants tab shows one readable row with the custom columns.

## Scope

In:

1. **Domain**: typed event settings (venue, capacity, registration mode and window, consent text and version) with validation; the registration decision (open, approval, capacity → waitlist); CSV cell escaping.
2. **Passes** (`internal/pass`): Ed25519 signing keys in `DATA_DIR/keys` with rotation; tokens `EP1.<keyId>.<eventCode>.<passId>.<sig>`; QR PNG; pass card PNG; A6 PDF.
3. **Outbox**: `OutboxRepo` per event (memory and sheets), a worker that sends one email every 1.5 s with retries (2, 4, 8, 16 min), a daily cap (default 450) and no duplicate sends after a crash (rows left in `sending` become `failed` for a manual resend).
4. **SMTP** (`internal/mail`): go-mail transport, STARTTLS required (implicit TLS on 465), built-in templates for pass issued, registration received (pending approval) and waitlisted, with inline QR and PNG/PDF attachments. Tests against a fake SMTP server.
5. **Sheets adapter** (`internal/storage/sheets`): header-mapped tabs, per-tab cache with TTL and write-through, verify-before-write with one reload-and-retry, appends for logs and outbox, batch reads at startup, priority quota limiter, retries with backoff and `ErrBusy`, per-spreadsheet write lock, `Meta.schema_version` migrations. An in-process fake of the Sheets HTTP API runs the contract suite and the 429/5xx, limiter and TTL tests.
6. **Secrets and setup**: `DATA_DIR/secrets.enc` (AES-256-GCM under `EVENTPASS_SECRET_KEY`); a one-time setup token printed in the log; `/setup/google-check`, `/setup/smtp-check`, `/setup/complete`.
7. **API**: public registration, field CRUD and ordering, event settings, connect sheet, portal pass (`.json`, `.png`, `.pdf`), approval sending the pass email.
8. **CLI**: `check`, `admin add`, `migrate`, `export`, `keygen --pass`.
9. **Web**: setup wizard, event settings, form builder with live phone preview, public registration page with confirmation, portal pass with downloads.
10. **Docs**: Google service account and Gmail App Password setup.

Deferred (recorded in PROGRESS.md):

- Photo and file upload fields and the blob store: M2, with the staff card that shows photos.
- Invite-only registration: M4, with CSV import.
- CAPTCHA: M4.
- Editable email templates: M4 (M1 ships fixed, translatable templates).
- Drag-and-drop in the form builder: M4 (M1 has keyboard-friendly move up/down).

## Risks

- **Sheets quota**: 60 requests/min per service account. Registration costs about 2 writes (participant row, outbox append) plus outbox status updates. The limiter keeps headroom for scanners and the portal; background work backs off first.
- **Manual edits in the sheet**: rows may move when someone sorts. Every update re-reads the row by range and checks the ID first.
- **Duplicate emails on crash**: a row is marked `sending` before SMTP and `sent` after; on restart `sending` rows become `failed`, never re-sent automatically.
- **Real Google/Gmail verification** can't run in CI; the fake covers the API surface we use, and the manual gate run covers the rest.
